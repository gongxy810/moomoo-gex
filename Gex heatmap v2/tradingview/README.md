# Gex heatmap v2 for TradingView

1. Open a TradingView chart's Pine Editor, paste [`GexHeatmapV2.pine`](./GexHeatmapV2.pine), save, and add it to the chart.
2. In the OpenD board, set the symbol, expiry, strike count, Top N, `% King`, chart period and Replay cursor; wait for historical nodes to finish loading. Click **Export gex levels** → **Copy for TradingView indicator**.
3. Paste the complete multiline `GEX3` block into the indicator's **Snapshot input (GEX3)** setting. Use the same 1m or 5m chart period and session on TradingView to align candle times.
4. Use a chart with the same symbol and New York date. `SPXW` option strikes display only on a cash `SPX` chart, such as `TVC:SPX`; they are deliberately hidden on the `FOREXCOM:SPXUSD` CFD chart because the board has no verified cash to CFD mapping.

The gold and purple historical bubbles preserve the board's time bucket, mapped price, sign, strength, source and capture time. Native marks are circles; a derived mark is a diamond only when the board exported a real derived source. They draw behind candles. The King line is gold; Call Wall is cyan, Put Wall is pink, and coincident labels are combined. Fixed Day ±1σ and available ±2σ are blue dotted lines spanning the exported New York date. In Replay they are labeled `Hist Day`. The reference line is labeled `Spot`, `Delayed`, or `REF` at capture time.

The old seven-field `GEX snapshot` row remains available in the same dialog. `GEX3` includes historical nodes up to a conservative 38,000-character payload. If more history exceeds that size, the dialog reports how many older nodes were omitted. The indicator draws up to 480 nodes in the visible chart window at once, leaving room under Pine's 500-label limit for price labels; scrolling or zooming updates which imported nodes are drawn. It also accepts older `GEX2` data, but that format has no historical trail. Pine does not read the local OpenD service or automatically refresh when the board changes; re-copy after a capture. A missing fixed Day Range is `na`; it is never filled from the Live Cone. Replay exports only nodes observed by its cursor. This script does not fabricate Velocity, a Live Cone or an SPX-to-CFD mapping from one static snapshot.
